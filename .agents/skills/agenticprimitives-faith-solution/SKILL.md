# Build a faith-domain solution

1. Select Faith core plus only the domain profile(s) required by the user journey.
2. Preserve distinctions among identity/classification, a locally defined people community, gatherings/ekklesia, engagement activity, outcomes, evidence, and claims.
3. Map people, organizations, service agents, content, commitments, activities, outcomes, and assertions to Agentic Trust upper concepts.
4. Preserve local definitions, provenance, consent, sensitivity, and geographic/linguistic/religious facets.
5. Use the ontology bridge to find package types, content primitives, attestations, relationships, A2A skills, MCP schemas, and audit evidence.
6. Keep field-sensitive records in the appropriate person/organization/service vault and expose only authorized projections.
7. Validate example graphs and competency queries.
8. Add explicit uncertainty and source attribution; do not turn classification data into unsupported facts.
9. Never infer access or operational authority from a ministry role or ontology relationship alone.

If no exact domain profile exists, propose an extension in the domain ontology rather than placing application-specific terms in the upper ontology.
