# Release binding

Which package versions, contract addresses, skills, and endpoints belong together —
as generated artifacts, not prose. If you (or your coding agent) are about to guess a
version or copy an address from a README, stop and resolve it from here.

## The manifest

[`release-manifest.json`](../release-manifest.json) at the repo root binds one release:

| Surface | Artifact |
| --- | --- |
| 65 published `@agenticprimitives/*` pins | [`catalog/packages.json`](../catalog/packages.json) |
| 34 contracts on Base Sepolia | [`contracts/deployments/eip155-84532/`](../contracts/deployments/) |
| 62 released ABIs | [`contracts/abis/`](../contracts/abis/) |
| 13 developer Agent Skills | [`skills/`](../skills/) |
| Live Home / A2A / MCP endpoints | `endpoints` in the manifest |

All of it is generated by `pnpm release:generate` from the pinned package tree and the
installed `@agenticprimitives/contracts` artifact. CI rejects drift. Nothing is
hand-maintained.

## Resolve a contract, never copy it

Each deployed contract has one record: address, chain, source package, ABI path, and
the ABI's sha256.

```ts
import record from '../contracts/deployments/eip155-84532/base-sepolia-2026.08.0/delegationManager.json';

if (chainId !== record.chain.chainId) throw new Error('wrong chain');
// record.address — checksummed
// record.artifacts.abi — path to the released ABI
```

`index.json` in the same directory lists every contract plus operational roles
(deployer, governance guardian) — roles are accounts, not contracts, and never get
deployment records.

## Checks

```sh
pnpm release:validate   # offline: schemas, pin coherence, ABI digests, checksums
pnpm doctor             # live: npm pins exist, Home/A2A/MCP respond
pnpm doctor:full        # + eth_getCode confirms every address still has runtime code
pnpm skills:check       # skill projections (.claude/.cursor/.agents) match skills/
```

`release:validate` also cross-checks the root `pnpm.overrides` against the release
pins, so the workspace cannot silently disagree with the manifest.

## Developer MCP server

`packages/dev-mcp` is a read-only stdio MCP server exposing the manifest, package
pins, deployment records, ABIs, and skills as 9 tools. Point your editor at it and
the agent resolves facts instead of inventing them:

```sh
# Claude Code
cp .mcp.json.example .mcp.json
# Cursor
cp .cursor/mcp.json.example .cursor/mcp.json
```

It holds no keys, signs nothing, broadcasts nothing, and cannot touch a vault.

## Cutting a new release

```sh
pnpm release            # generate + sync skills + validate
pnpm doctor:full        # confirm the world still matches
```

Bump the release id in `scripts/generate-release.mjs` (or pass `--release`) when the
pinned tree or deployment set actually changes.
