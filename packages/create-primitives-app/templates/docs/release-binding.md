# Release binding

Which package versions, contract addresses, skills, and endpoints belong together —
as generated artifacts, not prose. If you (or your coding agent) are about to guess a
version or copy an address from a README, stop and resolve it from here.

## The manifest

[`release-manifest.json`](../release-manifest.json) at the repo root binds one release:

| Surface | Artifact |
| --- | --- |
| 75 published `@agenticprimitives/*` pins | [`catalog/packages.json`](../catalog/packages.json) |
| 43 contracts on Base Sepolia (public, verified) | [`contracts/deployments/eip155-84532/`](../contracts/deployments/) |
| 43 contracts on the estate chain (gated RPC, resolved) | [`contracts/deployments/eip155-34348/`](../contracts/deployments/) |
| 63 released ABIs | [`contracts/abis/`](../contracts/abis/) |
| 13 developer Agent Skills | [`skills/`](../skills/) |
| Live Home / A2A / MCP endpoints | `endpoints` in the manifest |

All of it is generated by `pnpm release:generate` from the pinned package tree and the
installed `@agenticprimitives/contracts` artifact. CI rejects drift. Nothing is
hand-maintained.

## Resolve a contract, never copy it

Each deployed contract has one record: address, chain, source package, ABI path, and
the ABI's sha256.

```ts
import record from '../contracts/deployments/eip155-84532/base-sepolia-2026.09.0/delegationManager.json';

if (chainId !== record.chain.chainId) throw new Error('wrong chain');
// record.address — checksummed
// record.artifacts.abi — path to the released ABI
```

`index.json` in the same directory lists every contract plus operational roles
(deployer, governance guardian) — roles are accounts, not contracts, and never get
deployment records. The typed-suffix subregistries are flattened to
`permissionlessSubregistries.<suffix>` so every record is one address.

Each chain's `index.json` says whether it has a public `rpc`. Base Sepolia does, and
`doctor:full` verifies runtime code there. The estate chain does not — its records are
resolved from the published package and the index says so; `doctor` reports them as
*unverified*, never as *present*.

## Checks

```sh
pnpm release:validate   # offline: schemas, pin coherence, ABI digests, checksums
pnpm doctor             # live: npm pins exist, Home/A2A/MCP respond
pnpm doctor:full        # + eth_getCode confirms every address still has runtime code
pnpm skills:check       # skill projections (.claude/.cursor/.agents) match skills/
```

`release:validate` also cross-checks the root `pnpm.overrides` against the release
pins, so the workspace cannot silently disagree with the manifest.

## Two Developer MCP servers, one rule

`packages/dev-mcp` is a read-only stdio MCP server exposing **this kit's** manifest,
package pins, deployment records, ABIs, and skills as 9 tools. Upstream's
`@agenticprimitives/devkit` ships `npx ap mcp`, which answers from the packages
installed beside it (exports, ontology terms, deployments, recipes, a doctor
report). Either one lets a coding agent resolve facts instead of inventing them; both
hold no signing key, read no vault, mint no authority, and invoke no production
effect. Neither is Home MCP (a person's entrance to their own agent) nor the runtime's
private MCP behind admission — confusing the three is the failure the upstream spec
warns about, and each server's first resource says which one it is.

```sh
# Claude Code
cp .mcp.json.example .mcp.json
# Cursor
cp .cursor/mcp.json.example .cursor/mcp.json
```

## `agentic.lock.json`

A product repository from `@agenticprimitives/create-app` carries an `agentic.lock.json`:
the coherent `@agenticprimitives/*` pin set, the digests of the projected rules
source, the doctor config, and (after `ap upgrade --pin-definitions`) the authority
shape of every archetype tool — so an upgrade that changes a tool's risk, resource
argument, or effects **stops for review** instead of landing silently. This kit's
[`schemas/agentic-lock.schema.json`](../schemas/agentic-lock.schema.json) describes the
shape; `release-manifest.json` is the kit-side equivalent for a release rather than a
product.

## Cutting a new release

```sh
pnpm release            # generate + sync skills + validate
pnpm doctor:full        # confirm the world still matches
```

Bump the release id in `scripts/generate-release.mjs` (or pass `--release`) when the
pinned tree or deployment set actually changes.
